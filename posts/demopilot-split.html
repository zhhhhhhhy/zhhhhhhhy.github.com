把 DemoPilot 拆一遍：一次真实对话里的 web coding

2026-10-05 # 复盘 # web coding # 架构

这一篇不是现成的观点，而是一次真实过程的复盘：我把自己的项目 DemoPilot 拆了一遍，边拆边和 AI 讨论，最后沉淀出一套"怎么做 web coding"的走法。记录它，是因为这个过程本身比结论更有价值——它是"人和 AI 一起把一件事想清楚"的样子。

01起点：为什么从 DemoPilot 开始

想写"AI 时代怎么做架构师"，但"架构"太抽象，不如直接拿一个真实项目拆。DemoPilot 是一个让 Agent Team 造 Agent Demo 的系统：人类负责目标、边界与验收，Agent 完成架构、前后端、测试与迭代。它天然就是"人负责意图、AI 负责实现"的样本。于是从它的第一个模块——意图——开始拆。

02意图模块：不断提问，真能把意图问清楚吗

DemoPilot 的第一个模块，是让使用者尽可能把意图表达清楚。我当时的方法是用不断提问来逼出意图。但这里有个真问题：这个"不断提问"，真的能把用户的目的问清楚吗？

结论是：能，但有边界。提问提升的是"表达的保真度"，而不是"意图本身的质量"。

// 提问能做到 vs 做不到

能做到：把用户没主动说出的约束逼出来；把"我以为说清了"变成"确认说清了"；对"模糊但已存在"的目标有效收敛。
做不到：用户自己也不知道答案时，提问只会让用户更困惑；提问维度错了会固化错误假设；表达清楚不等于意图正确；过度追问导致用户凑合；抓不到隐性约束（成本、合规、隐藏偏好）。

对应的改进方向：

  • 有维度地问——只围绕 边界 / 优先级 / 验收 / 约束 四个维度收敛，问完就停，不无限问。
  • 把问答沉淀成"一页纸意图声明"，最后让用户确认，而不是一堆散落的对话记录。
  • 最该问出来的是验收标准——意图最终要落到"什么算完成"（呼应 evaluate）。
  • 承认边界——几轮之后仍说不清，就明确告诉用户"目标需要你自己想清楚"。

03意图不清时，该不该生成

顺着往下：如果用户自己也不知道答案，是不是就不该生成？结论是：不是"不生成"，而是"不盲目标准生成"。

  • 意图完全模糊、连验收都说不出来 → 停下，不生成。
  • 意图大致有、细节不清 → 生成一个低成本草案当脚手架——人对实物比对着抽象问题更容易说清。
  • 意图清楚 → 才进入正式生成与迭代。

所以决策点不在"生成 or 不生成"，而在"以多高置信度、以什么形态生成"。这和 RAGForm"证据不足转人工"是同一套逻辑：不确定时，不硬生成一个错的答案。

04落地：批式提问 + 判定器 + 阈值

意图模块具体怎么实现？讨论出的结构：

  • 批式提问，按维度分批——不是一道一道问，而是按"边界 / 优先级 / 验收 / 约束"分批打，批与批不重复、不漏。
  • 用独立子智能体当判定器，对每一批回答评价"意图是否清晰"，而不是让主流程自己判断。
  • 阈值决定是否推进；但判定标准要先定义死——比如"用户能否独立写出边界 + 验收 + 至少一条约束"，否则判定器自己也会含糊。
  • 设最大轮数兜底——到上限还不清晰，降级为草案模式，而不是死循环。
  • 判定器输出依据（引用户原话证明"哪条说清了、哪条没有"），不只给分数，可追溯、可抽查。

一轮提问约 1~2 千 token，模型完全能接受，长度不是问题。

05生成阶段：最容易翻车的三个点

意图判定通过后进入生成。这一步看起来"没什么大问题"，其实恰恰是整个系统最容易翻车的地方：

  • 没有中途验收点——意图清楚不代表生成不跑偏。等整个项目生成完才发现方向错了，返工成本巨大。应该在每个子模块完成后让用户 / 判定器确认一次——这正是 human in loop 该出现的地方。
  • 生成任务内部也要拆——前端、后端、测试、环境……单 agent 长链路容易失焦。意图阶段拆的是"问题"，生成阶段拆的是"实现"。
  • 长上下文隐患在生成阶段累积——提问 1~2 千 token 没事，但生成一路累积会触长度上限，需要在途中把"已完成的上下文"压缩 / 归档。

06沉淀：这次对话得到的 web coding 方法

把这次讨论整理成几条可复用的走法：

// web coding 的方法清单

① 人负责意图与判断，AI 负责实现；过程不 in loop，结果必须 human in loop。
② 拆，是一切的地基：先拆"问题"（意图），再拆"实现"（生成）；每个单元要有"算完成"的定义。
③ 提问要有维度、要沉淀成声明、要逼出验收标准；意图不清就降级草案，不硬生成。
④ 生成阶段要有中途验收点、要拆内部、要防上下文膨胀。
⑤ 判定与评价要可追溯、要防误判、要有兜底。
